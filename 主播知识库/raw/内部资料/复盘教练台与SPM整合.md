# 与 SPM（操盘脑）的整合

> 分工不变：**SPM 对「事」，教练台对「人」。SPM 一个字不改。**
> 代码见 `coach/spm.py`，命令见 `python3 -m coach spm`。

## 三层整合

| 层 | 方向 | 做什么 | 状态 |
|---|---|---|---|
| **L0 打法卡 → 规则库** | SPM → 教练台 | 把 SPM 的打法卡转成教练台的规则 | ✅ 已实现 |
| **L1 场次 → SPM** | 教练台 → SPM | 每天从群里收的数据导给 SPM | ✅ 已实现 |
| **L2 效果分回流** | 教练台 → SPM | 「谁用了这张卡、第二天怎么样」 | ✅ 已实现 |

---

## L0 · 打法卡 → 规则库

SPM 的打法卡和教练台的规则**几乎同构**：

| 打法卡 | 规则 |
|---|---|
| 怎么做 / 怎么说 | `回复` |
| 失效信号 | `跟进`（到期就查这个信号） |
| 卡ID / 来源 | `来源` |

```bash
python3 -m coach spm cards data/spm-打法卡-14张.csv > 草案.ini
```

### 诚实边界：不假装能自动映射

卡的触发条件是**数据条件**（「付费占比>30%」「CTR跌超50%」），
而教练台只有时长、GMV、在线人数和主播的自述文本——**拿不到那些数据**。

所以导入器：
- 命中词只从**已知行业词表**里挑（中文不分词就做滑窗抽取，只会产出「断档时上」这种垃圾）
- 抽不出命中词的卡**整条注释掉**，老板填完取消注释即生效——规则库始终是合法的
- 原本靠数据触发的卡，逐条标出「这张卡原本靠 X 触发，教练台没有这些数据，请核对」

**宁可让老板改一行，不要假装懂。**

## L1 · 场次导出给 SPM

SPM 正死在它自己写下的死因上——验收题第 14.3-9：
「体系最大的死因是什么？」标准答案：**「没人回填数据」**。

教练台每天从群里收数据。导给它：

```bash
python3 -m coach spm export [起始日期] > sessions.csv
```

| 能填（10 列） | 留空（15 列） |
|---|---|
| 日期 · 主播 · 平台 · 时长 · 前台GMV · 店铺GMV · 平均/峰值/最低在线 · 讲解产品 | 总UV · 结算GMV · UV价值 · 客单价 · 退款率 · GPM · 各种漏斗率 · 千川消耗 … |

**留空的一律留空，不编。** SPM 第 7 律本来就要求缺数据报缺。
另附一列「主播原话」——这是 SPM 完全没有、而教练台每天都在收的东西。

## L2 · 效果分回流（SPM 缺的最后一环）

SPM 的公式：`效果分 = 采用该卡的场次中，达标场次占比 × 100`，
`<40` 降级、`<25` 淘汰、样本 `<5` 场标「观察中」。

**但它没有「谁用了这张卡」的数据来源**——它是被动问答的，没人记录。

教练台的 `reply_log.rules_hit` + `session.hit_target` 每天都在记这件事：

```bash
python3 -m coach spm scores
```

口径照抄 SPM，包括「样本<5场不下结论」这条实验律。

## ⚠ 先分清：底层逻辑 vs 打法卡

| | 是什么 | 能不能跨量级 |
|---|---|---|
| **底层逻辑** | 宪法 7 律、`GMV=UV×UV价值`、匹配律、赛马律、实验律、衰减律、风险律、数据律 | ✅ **通用，照搬** |
| **打法卡** | 梯队承接、人群包赛马、切片回流、私域撬公域… | ❌ **特定量级的战术，换量级即失效** |

**底层逻辑照搬，打法卡按量级重建。** 下面这条结论只针对打法卡那一层。

## 拿真实数据跑出来的结论：**大部分打法卡在她身上是死的**

把 14 张卡导进来，拿主播A 19 条真实复盘跑一遍：

```bash
python3 -m coach spm audit tests/fixtures/full_19.txt
```

| | 张数 | 卡 |
|---|---|---|
| 命中 | 5 | 憋单拉流 · 停留撬流 · 嗓音状态 · 净利还原 · 价格弹性测试 |
| **一次没命中** | **8** | 梯队承接 · 五分钟赛马 · 人群包赛马 · 情绪词云 · 流量分流话术 · 私域撬公域 · 切片回流 · 新老粉健康 |

**原因不是转换没做好，是量级不匹配。**

主播A是视频号小主播，峰值在线 **7–22 人**。
而这些卡来自交个朋友、辛选、东方甄选、广东夫妇、遥望——**头部大直播间**。
梯队承接要有货盘梯队，人群包赛马要投千川，切片回流要有剪辑团队，
私域撬公域要有企微池子。**她一个都没有，19 条复盘里一次都没提过。**

### 这条结论有直接的钱的意义

> **别再花钱买头部打法卡了，这个量级的主播用不上。**
>
> 调研里那道闸门问「打法卡能不能跨账号迁移」——
> 在这批真实数据上，答案是：**不能跨量级迁移。**
> 同量级的经验（比如另一个视频号小主播）才有迁移价值。
>
> **再强调一次边界：不能迁移的是打法卡（战术），不是底层逻辑。**
> 宪法 7 律、价值恒等式、匹配律、实验律那一层跨量级通用，一个字不改。

## 审计工具：让老板自己能查

与其指望一次调对命中词，不如给他一个能查的工具：

```bash
python3 -m coach spm audit <复盘文本文件>
```

它会标出两类问题：
- **命中率 > 60% 且有命中词** → 命中词太泛，多半撞上了模板里的固定文字
- **命中率 = 0** → 这条规则在这批主播身上是死的

### 这个工具是怎么来的

开发中真踩过两次：

1. 「人多接不住」在 19 条里命中 13 条——因为复盘模板第三段的标题
   就叫「三.**流量大**小应对措施」。修法：模板骨架不参与关键词匹配。
2. 「嗓音状态」命中 13 条——因为命中词里有「状态」，
   而老板的模板里就有「今日直播状态：」，主播每天都写「状态可以」。
   修法：把过泛的词（状态、话术、情绪、互动）从行业词表里剔除。

**两次都是「模板自己的固定文字被当成了内容」。** 有了审计，下次能自己发现。

## 不做什么

- **不改 SPM 一行代码、一个字。** 宪法 7 律、全部公式、12 张表，原样不动
- **不替 SPM 判定主播去留。** 待岗考核那类决定全部人工
- **不把 SPM 拿不到的数据编出来给它。** 缺就是缺
